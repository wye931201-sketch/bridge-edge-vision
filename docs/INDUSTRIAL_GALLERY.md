# 四类受损照片的直观对比

`gallery` 导出裂缝、混凝土剥落、锈蚀和工业划痕四组，每组默认 24 张。每个数字文件夹只有原始图片和识别结果 JPG。根目录的 `打开对比.html` 可以左右查看，显示照片分组、模型、切片设置和候选数量。

新版识别结果包含独立的状态栏、醒目候选框和可选预测掩码；未检出不会只另存一张外观相同的照片。状态栏与显示放大只改变展示，不改变输入模型的原始照片。`rendering` 记录显示缩放及照片在结果卡中的起点。

浏览器可通过 `http://127.0.0.1:8765/comparison/` 打开；支持按照片类型、目标类别未检出、无任何候选和文件名查找。类别候选出现并不等于检测框位置正确，准确性另由验证集匹配评估。[增强推理报告](INSPECTION_OPTIMIZATION.md)。

## 图片怎样选

前三组来自既有 dacl10k-v2 固定验证集，按原始标注分别选含 Crack、Spalling、Rust 的照片；每组按文件名取前 24 张，跳过前组已经使用的照片。原始照片可能同时具有多类病害。

划痕图片来自 [NEU-DET 的 GitHub 镜像](https://github.com/siddhartamukherjee/NEU-DET-Steel-Surface-Defect-Detection)，固定到 `configs/industrial_sources.json` 的提交，选择前 24 个划痕图片路径。下载器逐一验证图片与 XML 的 Git blob 哈希、200×200 尺寸、框范围及类别，要求 XML 确实包含 scratches。部分照片同时标注 inclusion；保留这种多目标情况，不改写标注。

这些选择在推理前由来源标注和文件名决定，不按识别效果挑图。来源类别表示这张照片属于哪个展示组，不代表模型成功检出了该类别。没有检出、误分类和多余候选都会保留。

## 模型来源

- 桥梁照片使用本项目已完成预实验的 YOLOv8n ONNX 模型；legacy 为 768 像素切片，auto 可复用已验证的全图与多尺度方案，实际单次模型输入为 384。切片坐标还原并合并 NMS。
- 工业照片使用 [winthegame259/steel-surface-defect-detection v1.0.0](https://github.com/winthegame259/steel-surface-defect-detection/releases/tag/v1.0.0) 的六类 ONNX 模型。下载时核对发布资产的 SHA256，运行时核对模型哈希、类别元数据及输入形状。
- 工业模型是第三方预训练模型，未在本项目重新训练。使用独立类别表和颜色，不能与桥梁五类 ID 混用。
- 可选裂缝辅助是 [Cucom/UAVCrack-R10](https://github.com/Cucom/UAVCrack-R10/releases/tag/v1.0.0) 的一个 ResNet34 U-Net 图。单图与六模型集成不同，不引用其竞赛分数作为本项目成绩。红色掩码与相应连通域框来自该图的实际预测；候选过滤参数由完整固定验证集比较。

所有结果图片均由实际模型推理后绘制；XML 仅用于数据来源检查，不参与预测框生成。工业推理和整个图库导出可在无 PyTorch 的 ONNX 环境中执行。

## 验证与许可

原图逐字节复制，记录原图、识别图和模型哈希。对比页不等于准确率评估；工业模型使用的训练划分与展示图片是否重叠尚未确认，因此不据此报告独立测试成绩，也不把上游成绩作为本项目实测。

[NEU 数据集维护者页面](https://faculty.neu.edu.cn/songkechen/zh_CN/zdylm/263270/list/index.htm)介绍六类钢材表面缺陷与引用要求，但未发现明确的标准数据许可。图片、XML 和工业权重仅缓存于本机，不随本仓库重新分发。上游模型项目代码为 AGPL-3.0；模型来源和数据来源分别保留记录。桥梁数据仍按原数据卡的 CC BY-NC 4.0 处理。

这是受损照片与识别结果的展示功能，不输出物理尺寸、严重程度或结构安全等级。
