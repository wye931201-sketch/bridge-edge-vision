# 实验与故障记录

第一版预实验按固定规则选择 768 张训练图和 160 张原始验证图，隔离两张方向不确定图后实际使用 766/160，384 输入、15 轮与一个随机种子。结果由运行脚本保存，不把环境检查或模型结构前后向检查当作检测准确率。

## 训练前的数据问题

两张可解码 JPEG 在 EOI 标记后存在额外字节，训练库自动修复会改变准备目录中的文件哈希。当前准备流程保留原始字节及其哈希，建立独立副本，仅裁去最后 EOI 之后的字节，同时记录准备文件的独立哈希和变换类型。此操作不重采样、不改变图像像素。原始数据与准备数据分别可追溯。

另查出两张训练图片的 EXIF 方向为 6，而源尺寸描述为原始栅格尺寸。坐标系尚未确认，准备版本 2 将两张图隔离，避免擅自旋转标注。最终三组对照均在这一份新数据清单上重跑；早先 768/160 的基线与后端检查仅是排查过程证据，不作为最终精度对照。

跨划分 dHash 提示的三对图片已经逐对目视检查，尚未确认重复；具体理由见 `artifacts/data/perceptual_review.json`。这不代表完成了所有标注的人工核验，也不证明桥梁身份隔离。

## CUDA 长运行问题

当前 Windows/PyTorch/CUDA 组合在训练中出现过非有限损失、非法内存访问以及 pinned allocator 原生异常。短时结构检查通过没有覆盖这种错误。依次测试了同步 CUDA、关闭融合 AdamW、关闭 cuDNN；单独改变这些条件仍观察到失败，不能据此认定某一个算子或驱动是根因。

独立安装官方 PyTorch 2.9.1 + CUDA 12.8 后仍复现非有限值。正式预实验改用独立 PyTorch 2.9.1 CPU 环境，推理提供纯 ONNX CPU 路径。问题原因仍未确定，不能据此断言显卡损坏或某个软件版本存在普遍缺陷；CUDA 长训练在本机当前执行环境下尚未验收。

当前保守训练路径使用无 pinned memory 的加载器、同步主机到设备传输、显式非融合 AdamW、非 foreach 梯度裁剪，并按实验配置控制 cuDNN。遇到非有限梯度或损失立即失败，未达到完整轮数的运行不能登记为完成。实际采用的设置与软件版本保存在实验记录中。后续恢复优化路径需要重新跑完整训练与精度/速度验收。

Windows 默认设置 `CUDA_LAUNCH_BLOCKING=1`，最终三组配方均明确设置该值。早先使用 0 的基线只属于排查过程。部署测速会单独记录运行时设置。

## RepViT 输入约定

YOLO 预处理输出 RGB [0,1]；ImageNet RepViT 骨干需要均值 `[0.485,0.456,0.406]` 和标准差 `[0.229,0.224,0.225]`。标准化放在骨干内部，随 PyTorch/ONNX 共同执行。补齐此前遗漏后重新运行两个 RepViT 版本，未完成的旧试跑不用于最终消融。

失败和中断目录保留在本机数据区，新运行使用新名称。正式结果文件只纳入预算完成且验证成功的运行；诊断运行不能作为模型对照结果。

实验记录包含本地启动时的 Git 基准修订。公开仓库通过 GitHub 接口发布，提交标识可能不同；核心训练代码另有 SHA256 指纹，可用 `bridge_edge.utils.training_fingerprint` 对照当前源文件。训练耗时为本机经过时间，可能包含系统休眠或等待，部署速度以独立预热后的基准测量为准。
