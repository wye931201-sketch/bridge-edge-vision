# 从第一版工程到论文实验

## 当前研究问题

在有限算力设备上，怎样改善桥梁细小表观病害的定位，同时控制延迟、内存与模型规模？

手机端原方案提出 RepViT + YOLO、自适应多尺度增强与 Jetson。当前实现将核心检测单独建立，本阶段不混入云端模型、断网调度、无人机或机器人控制。

## 三个可运行的对照

| 模型 | 作用 | 初始化 |
|---|---|---|
| YOLOv8n | 小型通用检测基线 | 官方 COCO 权重 |
| RepViT + YOLO 检测头 | 骨干替换的工程比较 | RepViT ImageNet，检测头初始化 |
| RepViT + AMSF + YOLO | 多尺度模块消融 | 与上一行共享相同初始状态，新增 AMSF 单独初始化 |

AMSF 用三个空洞深度卷积分支、图像条件权重和残差增益组合标准算子。它是待验证的实验设计，不因模块命名就构成论文创新。RepViT 替换也不保证比 YOLOv8n 更小或更快，必须报告实际结果。

YOLOv8n 和 RepViT 的预训练来源不同，因此两者的差异属于工程配置比较。RepViT 与增加 AMSF 的版本才用于较受控的模块消融；训练开始前代码会核验初始化没有在 Ultralytics 重建模型时丢失。

## 第一阶段验收

- 固定真实数据、类别定义、标签转换与划分。
- 在真实图片上完成训练、验证、图片推理和本地界面演示。
- 保存权重、数据、配置哈希及逐轮损失。
- 导出 ONNX，检查原始输出数值与检测框一致性。
- 记录本机真实耗时，不以桌面 GPU 代替 Jetson 数据。

## 正式实验协议

| 维度 | 建议执行方式 |
|---|---|
| 重复性 | seeds 2026 / 2027 / 2028，报告均值和标准差 |
| 精度 | AP50、AP50:95、每类 AP、Precision、Recall；标明验证/测试 |
| 细小目标 | 按目标像素面积分组；明确阈值定义 |
| 效率 | 参数量、输入尺寸、FP32/FP16/INT8、峰值显存、p50/p95 延迟 |
| 消融 | 相同数据、分辨率、训练轮次、种子与共享初始化，比较 AMSF 开/关 |
| 泛化 | 不参与调参的跨桥梁/独立来源测试集 |
| 部署 | 同一权重在 PyTorch、ONNX、TensorRT 上做精度与速度复测 |

全量与多种子任务是后续正式实验，不能用单种子预实验表格替代。没有独立测试时只称 validation 结果；公开基准比较需使用相同数据版本和评价任务。

## 求职与比赛展示

演示应能现场完成：选择巡检图片 → 本地检测 → 查看类别与位置 → 导出证据 → 展示可复现的速度/精度记录。代码结构、测试、API 和部署文档可作为工程能力证据。

后续按实际赛事规则安排硬件、功耗和现场演示。Jetson、摄像头或机器人部分在实物验证前不列为已完成成果。

## 研究边界

表观检测结果属于疑似病害线索。尺寸量测需要标定或尺度参照，结构安全评价需要结合工程资料与专业判断。论文的贡献应来自明确问题、可检验方法与可靠实验，而不是代码行数。
