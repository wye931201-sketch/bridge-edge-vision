# 从第一张图走完整个工程

先运行本地网页，使用固定验证样例得到一张标注图与一个 JSON，再按下面的顺序阅读代码。每一步都有可检查的输出。

| 顺序 | 代码 | 要理解的事情 | 检查输出 |
|---|---|---|---|
| 1 | `data/download.py` | 从固定版本取得图片，验证字节与原始划分 | 下载清单和 SHA256 |
| 2 | `data/prepare.py` | 把多边形来源的包围框转成五类 YOLO 标签 | 图像/标签清单、隔离原因 |
| 3 | `data/audit.py` | 检查越界、文件变化和重复候选 | 类别数量、负样本、审计状态 |
| 4 | `models/layers.py` 与模型 YAML | RepViT 的三个输出尺度如何接入检测头 | 通道数、步长、参数量 |
| 5 | `training.py` | 初始化、相同预算、种子及非有限值处理 | 配方、源码指纹、逐轮指标 |
| 6 | `runtime/geometry.py` | 缩放填充、坐标还原和分类别 NMS | 单元测试、原图像素坐标 |
| 7 | `runtime/engine.py` | 两种后端如何输出相同结果格式 | 标注图、置信度、权重哈希 |
| 8 | `server.py` 与 `web/` | 上传、选择模型、推理和本地历史 | HTTP 验收、可下载的记录 |
| 9 | `deployment.py` | 导出之后如何确认数值与检测框一致 | 原始输出误差、匹配框、p50/p95 |

## 用真实证据介绍项目

- 说明五类标签的来源、训练/验证样本数和原始分割任务与当前检测子任务的区别。
- 用实验 JSON 说明数据版本、随机种子、训练轮数和模型权重，而不是只展示一张效果图。
- 解释普通缩放为什么可能丢失细裂缝，切片为什么需要把坐标映射回原图并再次 NMS。
- 用固定样例的跨后端一致性与禁止联网的进程检查，说明本地推理的实现依据。
- 展示当前实测设备及运行后端；用多种子、跨桥梁与实物设备实验继续检验结论。

## 下一阶段的研究工作

先人工检查一批真实标签与漏检图，分别统计细裂缝、遮挡、远距离、小目标和光照问题。随后使用全量训练集与固定验证集，完成至少三种子的相同预算对照。外部采集测试数据应按桥梁或拍摄批次隔离。

只有当精度、时延、模型大小和误检/漏检案例形成一致证据，才确定模块改进是否值得继续。论文的方法贡献还需要文献比较与消融支持。Jetson、摄像头与毫米尺寸标定按实际设备逐项验证。
